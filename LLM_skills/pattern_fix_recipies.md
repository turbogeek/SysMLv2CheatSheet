# SysML v2 Pattern & Semantic Fix Recipes

This file documents semantic, structural, and logical anti-patterns generated by LLMs when writing SysML v2 code. 
Unlike `fix_recipies.md`, the errors in this file **will not be caught by the official SysML v2 validator** (they are syntactically valid but structurally incorrect). 

When generating SysML v2, the LLM should cross-reference its generated output against the Regex patterns below to ensure structural integrity.

---

## 1. Invalid Port-to-Part Binding

**Anti-Pattern Description:** 
Syntactically, SysML v2 allows binding a `port` to a `part` (e.g. `bind myPart.myPort to myOtherPart;`). However, in strict modeling methodologies (like MagicGrid), you must only bind a `port` to a compatible `port` (e.g. `bind myPart.outPort to myOtherPart.inPort;`).

**Regex Pattern to detect:**
```regex
bind\s+\w+\.\w+\s*(?:to|=)\s*\w+\s*;
```
*(This looks for a binding where the right-hand side is just a single word (part), instead of `part.port`)*

**Fix Strategy:**
Ensure that both sides of the `bind` or `=` operator explicitly reference a port using dot notation.

*Incorrect:*
```sysml
bind battery.powerOut = system;
```
*Correct:*
```sysml
bind battery.powerOut = system.powerIn;
```

## 2. Using String IDs Instead of Direct Requirement Names in Satisfy

**Anti-Pattern Description:** 
Using the old angle-bracket string alias syntax (e.g., `<'REQ-01'>`) in `satisfy` statements instead of using the direct short name identifier (e.g., `REQ_01`). While sometimes syntactically valid, it breaks specific traceability parsers.

**Regex Pattern to detect:**
```regex
satisfy\s+<'[^']+'>\s+by
```

**Fix Strategy:**
Replace the angle-bracketed string with the raw requirement identifier, and ensure the requirement definition matches this format.

*Incorrect:*
```sysml
satisfy <'REQ-FUNC-01'> by display;
```
*Correct:*
```sysml
satisfy REQ_FUNC_01 by display;
```
