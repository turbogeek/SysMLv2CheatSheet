Issue 8: State machine tutorial view does not render a useful view
Problem
The StateMachine_Tutorial.sysml example parses successfully, but the initial view configuration did not produce an expected state-machine diagram in Cameo. The view had only top-level state elements without full transition rendering, instead of the expected view with a connected graph with labels on transitions.

Impact
The tutorial appears broken to users even though the model is valid. This creates confusion about SysML v2 syntax, view configuration, and expected Cameo behavior, and slows onboarding/testing.

Evidence
Original tutorial file: StateMachine_Tutorial.sysml
Working result confirmed: (see below)

Key observations from validation:
Transition arrows rendered more reliably when using an exhibited state usage as the exposed target.
Transition labels appeared when explicit accept trigger events were added.
Clutter reduced by using a state-focused filtered view instead of a broad graphical view.

Requested Change
Update the tutorial guidance/example to use a Cameo-stable pattern:
- Define the machine under the part, then use exhibit state for the machine usage.
- Expose the exhibited usage in the view.
- Use a state-focused view with EssentialElementsFilter and NonStandardLibraryElementFilter.
- Include explicit accept trigger events on transitions that should display labels.
- Add a short note in the tutorial that broad graphical views can surface unrelated meta elements.

Done When
The tutorial example renders a state machine with all transitions visible and labeled.
Yellow→Red displays guard/effect label.
View does not show broad unrelated meta elements such as doc/comment/assert/feature/step blocks.
A user can paste the example into Cameo and get consistent output without manual trial-and-error.

Working Example

```
package StateMachine_Tutorial {
    private import DS_Views::SymbolicViews::*;
    private import DS_Views::SymbolicViewsByExpression::*;
    private import SysML::Systems::*;
    
    /* Define the component containing the machine */
    part def TrafficLight {
        /* Local actions defined in part scope can access part attributes */
        action def LogStatus;
        item def RedToGreenTimeout;
        item def GreenToYellowTimeout;
        
        /* The machine behavior */
        state def LightLogic {
            /* Initial entry point */
            entry ;
            then Red;
            
            state Red;
            state Yellow;
            state Green;
            
            transition redToGreen first Red accept redToGreenTimeout : RedToGreenTimeout then Green;
            transition greenToYellow first Green accept greenToYellowTimeout : GreenToYellowTimeout then Yellow;
            /* Using if-guard and do-action */
            transition yellowToRed first Yellow if true do action log : LogStatus then Red;
        }
        /* Usage of the machine */
        exhibit state logic : LightLogic;
    }
    view StateMachine_Tutorial : StatesNestedView, EssentialElementsFilter, NonStandardLibraryElementFilter {
        expose TrafficLight::logic;
        expose TrafficLight::logic::**;
    }
}
```
